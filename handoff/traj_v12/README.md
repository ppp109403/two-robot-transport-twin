# traj_v12 — 차체 궤적을 **실제로 따라가는** 첫 판

2026-08-06. `traj_v2` 실기 확인 이후 다음 후보.

```
policy.onnx   md5 b58855f52385ab7654ccc4b2964e914e   58 -> 8
policy.pt     md5 d10b57cc5bce6f3145217f2f5693d131
ee_obs.py     md5 9952aaf0741b371575666a9decd63618   **58 차원 — 반드시 교체**
model_1000.pt 학습 체크포인트 (재개용)
```

요청하신 대로 **정책과 `ee_obs.py` 만** 보냅니다. 브리지(`policy_runner_traj.py`)는
로봇 PC 것을 기준으로 쓰시고, 관측 조립만 이 파일로 갈아 주세요.

## 1. v2 실기 관찰에 대한 답

> "V2 정책으로 움직이는 것까지 확인완료 — 베이스가 확실히 지멋대로 움직임"

그 문제를 겨냥한 판입니다. 차체 참조 궤적을 **관측으로 받고 보상으로 따라갑니다.**
실제 플래너 궤적 25 개로 잰 결과::

```
                 EE 오차    자세      차체 편차    3cm 통과
v6 (참조를 보기만)  10.9 mm   3.3 도    0.488 m      88 %
v12 (따라감)       13.9 mm  10.5 도    0.240 m      84 %
```

**차체 편차가 절반**입니다 (0.488 -> 0.240 m). 계획별로 짝지어 보면 25 개 중 24 개에서
v12 가 낫습니다. 플래너 `base_margin` 권장치가 **0.71 -> 0.53 m** 로 내려갑니다.

.. note::
   자세오차는 v6 보다 나쁩니다 (3.3 -> 10.5 도). 차체를 따라가느라 팔이 쓰는 자유도가
   줄어든 대가입니다. 위치오차는 거의 같으므로 **EE 를 어디에 두느냐는 잘 맞고,
   어느 방향으로 트느냐가 덜 정확**하다고 보시면 됩니다.

## 2. **가장 중요** — EE 목표 높이를 0.55 m 로 고정할 것

이 판은 목표 높이 **0.55 m 한 점만** 학습했습니다. 벗어나면 급격히 나빠집니다::

    0.55 m   EE  13.9 mm     정상
    0.60 m   EE  72.6 mm     5 cm 벗어나니 5 배

`plan_adapter` 가 2D 계획에 얹는 z 를 **0.55 로 고정**해 주세요.

.. warning::
   이건 이 판의 결함이고 다음 판(v13)에서 없앱니다. 그때까지는 운용 제약입니다.
   저희 쪽에서 처음에 0.60 으로 평가했다가 "정책이 망가졌다" 고 잘못 판정했습니다 —
   같은 함정에 빠지지 마시라고 적어 둡니다.

## 3. 관측 58 차원 — v2(52) 도 v6(60) 도 아닙니다

```
[ 0: 6]  arm_joint_pos      j1..j6 기본자세 기준 상대각 [rad]
[ 6:12]  arm_joint_vel      j1..j6 [rad/s]
[12:14]  base_twist         [v_x, omega_z]        /odom 의 twist
[14:23]  pose_command       목표 xyz 3 + rot6d 6   base_link 프레임
[23:32]  ee_pose            현재 EE xyz 3 + rot6d 6
[32:38]  ee_pose_error      위치오차 3 + 자세오차 axis-angle 3
[38:46]  actions            직전 스텝의 raw action 8
[46:52]  target_vel         목표 선속도 3 + 각속도 3
[52:56]  base_ref_error     dx, dy (base 프레임), sin(dth), cos(dth)
[56:58]  base_ref_twist     v_ref, omega_ref  (차체 프레임)
```

.. warning::
   **v6(60 차원) 것을 잘라 쓰면 안 됩니다.** v6 는 `[52:54]` 에 `wrap_margin` 이
   한가운데 들어 있어서, `[:58]` 로 자르면 `base_ref` 가 **두 칸 밀립니다**::

       v6   [:52] 기본 | [52:54] wrap_margin | [54:58] base_ref | [58:60] twist
       v12  [:52] 기본 |                     | [52:56] base_ref | [56:58] twist

   밀려도 **에러가 안 납니다.** 차원이 맞으니 정책은 그냥 돕니다 — 조용히 이상하게
   움직일 뿐입니다. 반드시 이 폴더의 `ee_obs.py` 로 교체하세요.

검증은 이미 했습니다 — 시뮬 실제 관측과 대조해서 최대 차이 **1.2e-7**.
(`target_vel` 만 2.1e-2 인데, AMCL 이 추정한 yaw 로 회전시키기 때문입니다.
참값 quat 을 쓰면 9.5e-8 로 떨어집니다. v6 때와 같은 알려진 항목입니다.)

## 4. 실행

로봇 PC 매뉴얼 그대로이고 `model_path` 만 바뀝니다::

    python3 ~/ee_track_ppo/traj/policy_runner_traj.py --ros-args \
        -p model_path:=/home/amr2/ee_track_ppo/traj_v12/policy.onnx \
        -p joint_target_topic:=/servo_target_cmd \
        -p base_hold:=false \
        -p odom_topic:=/odom -p cmd_vel_topic:=/cmd_vel_policy \
        -p max_lin_vel:=0.15 -p max_ang_vel:=0.5

차체 참조 토픽(`/base_ref_pose`, `/base_ref_twist`) 이 **반드시 들어와야** 합니다.
안 들어오면 관측 6 칸이 0 으로 남고, 정책은 "이미 계획 위에 서 있다" 고 믿습니다.

## 5. 플래너 파라미터 — 두 개를 낮춰 주세요

주신 실행 명령과 이 판이 학습한 범위를 대조하면::

    파라미터          주신 값    v12 학습 범위                 판정
    ee_v_max          0.40      EE 속력 95% 0.218, 최대 0.39   **0.25 로 낮출 것**
    reach_max         0.75      EE-차체 거리 95% 0.58          **0.60 으로 낮출 것**
    v_max (차체)      0.35      차체 속력 95% 0.115            무방 (러너가 0.15 로 캡)
    reach_min         0.25      95% 하한 0.31                  OK
    ee_forward_min    0.1       앞쪽 유지                      좋음 — 그대로 두세요

`reach_max` 를 낮추는 이유는 기구학입니다. IK 로 재보니 팔이 닿는 범위는
**팔 base 기준 반경 0.15 ~ 0.50 m** 이고, 팔 base 는 차체 중심에서 앞으로 0.205 m 에
있습니다. 그래서 차체 기준 0.75 m 는 방향에 따라 못 닿습니다::

    팔 base 기준 도달 (TCP 0.55 m)   방위각과 무관하게 대칭
      반경 0.10 m      X   너무 가까움
      반경 0.15~0.50   .   전 방향 도달
      반경 0.55 이상   X   너무 멂

`ee_forward_min:=0.1` 은 그대로 두시는 게 좋습니다 — 목표를 앞쪽에 두는 것이
도달 영역 안에 머무는 데 도움이 됩니다.

## 6. 안전 — 처음에는 팔 정지를 손에 두고

루프이득(자기 되먹임 크기)이 v2 보다 큽니다::

              중앙     최대     1 초과 자세
    v2 (실기)  0.561      -          -
    v6         1.113    2.466      65 %
    v12        0.953    2.383      40 %

v6 보다는 낫지만 v2 보다 훨씬 큽니다. **L1+R1 (매니퓰레이터 JOYSTICK 전환) 을
손에 두고** 시작해 주세요. 팔이 스스로 떨기 시작하면 그 즉시 전환하시면 됩니다.

.. note::
   이 값은 시뮬 기구학만으로 잰 것이라 실기 값과 정확히 같지는 않습니다.
   같은 도구로 v2 를 재면 실기값을 2 % 안에서 재현했으니, 정책간 비교는 믿을 만합니다.

## 7. 순서 제안

```
[1] ee_obs.py 교체 -> python3 ee_obs.py "전체 통과" 확인
[2] plan_adapter 의 z 를 0.55 로 고정
[3] ee_v_max 0.25, reach_max 0.60 으로 플래너 재실행
[4] 방 안에서 INITIAL SETUP -> EXECUTE
[5] 타겟 TCP 와 실제 TCP 오차 기록 (말씀하신 오차분석)
    + 차체가 계획 경로에서 벗어난 거리도 같이 -> 저희 0.240 m 예측과 대조
```

[5] 의 두 숫자를 주시면 시뮬 예측이 실기에서 얼마나 맞는지 처음으로 확인됩니다.
지금까지 그 대조가 없어서 시뮬 지표만 보고 판단해 왔고, 오늘만 그 때문에 두 번
잘못 판정했습니다.
