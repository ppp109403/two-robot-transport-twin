.. note::
   자세 숫자를 판 간에 그대로 비교하면 안 됩니다. v12/v17 의 값은 **90 도 어긋난
   목표**를 기준으로 잰 것입니다. 실물 막대 기준으로 정렬되는 것은 v24/v28 뿐입니다.

### 어떻게 얻었나

v22(= v17 + 90 도) 는 EE 가 v17 궤도를 그대로 탔지만 **자세가 역행**했습니다
(1.148 -> 1.276 -> 1.279 rad). 원인은 큰 오차에서 tanh 칸 셋(std 0.30/0.12/0.05) 이
전부 포화해 **자세를 포기하는 것이 거의 공짜**이기 때문입니다.

v24 는 큰오차 칸(std 0.8) 을 가중치 0.20 으로 넣어 자세를 고쳤지만 EE 가 4 배 나빠졌습니다.
v28 은 같은 칸을 **0.06** (0.3 배) 으로 넣어 "포기가 공짜만 아니게" 했습니다.

### 손 떨림에 대해 — **필터로는 못 고칩니다**

떨림 스펙트럼을 쟀습니다 (`scripts/eval_tremor.py`)::

    지배 주파수   0.20 Hz
    대역별 세기   0~1 Hz  79.6 %   1~3 Hz 12.1 %   3~7 Hz 6.0 %   7~15 Hz 2.4 %
    떨림 rms      4.91 도 (지령),  3.45 도 (실제)

**저주파(0~1 Hz)가 80 % 입니다.** 고주파 잡음이 아니라 **되먹임 한계주기**입니다.
저역통과 필터(브리지 ``follow_gain`` 낮추기) 를 걸면 위상여유를 깎아 **오히려 악화**될
수 있습니다. 하지 마시길 권합니다.

실제관절이 지령보다 저주파 비중이 더 큽니다 (93.5 % vs 79.6 %) — 서보가 이미 고주파를
걸러내고 있어서 필터를 더 걸 여지가 적습니다.

.. warning::
   루프이득이 지금까지 중 가장 높습니다. **L1+R1 (매니퓰레이터 JOYSTICK 전환) 을 반드시
   손에 두고** 시작해 주세요. 떨림이 심하면 즉시 전환하시고, 그 자체가 다음 판의

## 3. 실행

```bash
python3 ~/ee_track_ppo/traj/policy_runner_traj.py --ros-args \
    -p model_path:=/home/amr2/ee_track_ppo/traj_v28/policy.onnx \
    -p joint_target_topic:=/servo_target_cmd \
    -p base_hold:=false \
    -p odom_topic:=/odom -p cmd_vel_topic:=/cmd_vel_policy \
    -p max_lin_vel:=0.15 -p max_ang_vel:=0.5
```

운용 조건::

    EE 목표 높이   0.55 m 고정          (학습 범위 0.50~0.60)
    목표 요        **-90 도 보정 필수**
    ee_v_max       0.25
    reach_max      **0.60 으로 낮출 것**   (아래 참고)
    base_margin    0.25 m 면 충분 (차체 편차 중앙 0.094, 95% 0.30)

### `reach_max:=0.75` 를 낮추시길 권합니다

IK 로 잰 팔 도달 범위는 **팔 base 기준 반경 0.15~0.50 m** 이고, 팔 base 는 차체 중심에서
앞으로 0.205 m 에 있습니다. 차체 기준으로는 방향에 따라 0.30~0.70 m 입니다.
**0.75 m 는 어느 방향으로도 안 닿습니다.**

닿지 않는 목표가 오면 정책은 차체를 움직여 메워야 하는데, 차동구동은 옆으로 못 가서
방향을 틀었다 되돌립니다 — **지그재그로 보일 수 있습니다.** 학습 데이터의 EE-차체 거리는
95 % 가 0.544 이므로 0.60 으로 낮춰도 계획이 크게 달라지지 않습니다.

`w_max:=0.6` 도 후보입니다 — 학습 데이터의 차체 각속도는 95 % 가 0.058 rad/s 로
상한의 1/10 입니다. 지그재그가 남으면 0.3 으로도 시험해 보실 만합니다.
